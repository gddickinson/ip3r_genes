# INTERFACE.md — Module Navigation Map

> Read this **before** opening any source files. Each `.py` is < 500 lines
> and has one focused responsibility.

## Top-level

| File | Purpose |
|------|---------|
| `run.py` | CLI/GUI entry — `python run.py [--email you@example.com] [--headless --preset ip3r]`. |
| `PUBLICATION_ROADMAP.md` | **The multi-session publication plan**: session protocol, task ledger (S0–S24), emergent tasks, and the Decisions log — including the methodological rules inherited from the PIEZO project. Read at the start of every session. |
| `docs/session_briefs.md` | Detailed per-task instructions for every ledger row: goal, steps, completion criteria, outputs. |
| `docs/ip3r_background.md` | **The biology baseline.** Every statement tagged `[db]` (verified against a live database, with the query), `[lit]` (literature, verified in S0) or `[open]` (a question this project answers). Includes the ITPR/RYR hazard and the database-scale snapshot. |
| `docs/ip3r_review_2026.md` | **The literature review** — a 32-page, 137-reference, 12-figure review of the family (architecture, gating, regulation, cell physiology, paralogues, evolution, genetic models, disease, pharmacology, open questions), with §12 carrying the S0 claim audit and the figure provenance. **Generated — never hand-edit it**; edit `docs/review/*.md` and re-run `scripts/s0_review_build.py`. Cite its sources, never `ip3r_background.md`. |
| `docs/ip3r_review_2026.pdf` | The typeset review (A4, pandoc + xelatex), built by `s0_review_build.py --pdf`. |
| `docs/review/` | The review's **source**: numbered section files `00_frontmatter` … `12_methods_audit`, each under the 500-line limit. | `docs/figures/` | The review's 12 figures, png (GitHub) + pdf (the typeset build swaps the extension). **Generated** by `scripts/s0_review_figures.py`; never hand-edited, and never drawn from anything but a committed table. |
| `docs/analysis_catalogue.md` | **What the harvested data can answer** — the analysis menu behind ledger rows S15–S22, each with its inputs, method, deliverable and invalidating caveat, plus the report skeleton mapping analyses to manuscript sections. |
| `CLAUDE.md` | Session-start instructions, conventions, the family definition rule. |
| `INTERFACE.md` | (this file) navigation map. |
| `README.md` | User-facing docs + the project status board. |
| `SESSION_LOG.md` | Running notes per session: what ran, what resulted, what's next. |
| `FINDINGS.md` | **The biological story, task by task** — a dated plain-language entry appended after every completed task; unconfirmed claims marked *(pending: which task confirms it)*. |
| `roadmap.md` | Feature-development history of the app itself (inherited v1.0–v1.7 plus this project's changes). |
| `data_root.txt` | Path to the bulk-data root, read by `src/utils/data_root.py`. Edit one line to move storage. |
| `requirements.txt` | Third-party deps (`biopython`, `requests`). |
| `presets/` | Bundled JSON queries: `ip3r`, `ip3r_zebrafish`, `ip3r_discovery`, `ip3r_paralog_mine` (Compara paralog mine), plus the special-mode presets `ip3r_domain_scan` (`"mode": "domain_scan"`) and `ip3r_all` (`"mode": "exhaustive"` — full harvest + every analysis). Presets may carry `known_paralogs` and a `discovery` block of scorer-threshold overrides, honoured by both the CLI and the GUI Discovery dialog. |
| `cache/` | On-disk JSON cache (auto-created, gitignored). |
| `results/` | Committed analysis output — one directory per task. `s0_baseline/` holds the S0 database snapshot, the literature audit (`lit_claims.tsv`, `references.tsv`), the Ensembl endpoint probe and the rendered `report.md`; `s0_baseline/review_figures/` holds everything the review's figures are drawn from — InterPro domain coordinates, the 6DQN structural measurements (one subunit's Cα trace, the pore profile, `structure_meta.json`), the MAFFT conservation / identity / window tables, and the three curated tables. `benchmark_controls/` holds the S1 control benchmark: both panels as fetched, the InterPro domain hits, the MAFFT trace, the recall / specificity / bait-margin tables and the rendered `report.md`. `toolchain_manifest.txt` records the exact tool versions every later task shells out to. `census_v2/` holds S2: the enumerated census with a positive ITPR/RYR call and reason on every row, the rule audit, the unassigned profile, the sequence-level check of the call, the census-v1 delta with a verdict per missing accession, the representative table, the per-phylum core panel (the only FASTA committed — the census-scale ones are bulk) and four figures. `hmm_sweep/` holds S3's instrument: both seed sets and their MAFFT alignments, `itpr.hmm` / `ryr.hmm`, the enforced seed manifest, the reference-proteome manifest and DB stats, the calibration of profile assignment against S2's architecture call, and the sweep's assignments. `census_v3/` holds the merge: the census with **both** instruments' verdicts on every row, the novel hits, the call changes, the conflicts, the two-directional completeness tables, the jackhmmer convergence for all three seeds with its D10 verdict and per-seed model composition, four figures and the rendered `report.md`. |
| `results/s5_baits/` + `results/genome_ledger/` + `results/census_v4/` | **S5 — the genomic sweep's instrument and its 309-genome results.** `s5_baits/` holds the 38-bait panel (`baits.faa`), its rule provenance per bait, the per-candidate screen, `screen_self_test.tsv` (the screen's own negative controls, re-run on every build) and the intron calibration that sets miniprot's `-G`. `genome_ledger/` holds the pilot ledger long and wide, status counts, `locus_margins.tsv` (every found locus's family and paralog margins), the margin calibration that overturned the inherited attribution threshold (D25), `contiguity_bar.tsv` (D4's bar by class and scope), the measured S5b budget and the rendered `report.md`. `census_v4/` holds census v3 plus the sweep's 1,058 gene models with how each database holds their locus, the models the profiles declined to call, and the db-status counts. Per-genome evidence — raw miniprot GFF, rescue output, `summary.json` — is bulk and lives under `<data_root>/genome_sweep/<acc>/`, as do the census v4 model sequences. |
| `results/genome_manifest.tsv` | **S4 — the declared denominator.** One row per genome with accession, species, taxid, class, order, assembly name and level, RefSeq category, whether it carries a gene set, annotation source (D9), release date, total bp, scaffold/contig N50, size estimates, and the `reasons` it is in scope. `genome_manifest_notes.md` beside it is generated, never hand-edited. |
| `manuscript/` | The submission package, built by `scripts/s14_assemble.py` in S14a. See `manuscript/README.md`; nothing here is hand-edited except the numbered section files. |

## `scripts/` — roadmap-session tooling (not part of the app)

Ported and ready to use from session one:

| File | Purpose |
|------|---------|
| `dashboard.py` | **Project dashboard generator** (stdlib-only) → `dashboard.html` (gitignored): overall + per-task progress parsed from the roadmap ledger, a live panel for the in-progress task driven by `results/session_live.json`, key figures (explicit list first, then auto-discovered from `results/*/figures/*.png`, base64-embedded), and FINDINGS.md rendered. Meta-refreshes every 30 s. Session protocol step 0: `--open` plus a background `--watch`. |
| `figstyle.py` | **The one figure style every publication figure goes through.** Page geometry imported from `s14_lib`, so a figure is drawn at the width it is placed at. The validated palette: `PARALOG` (the fixed ITPR1/2/3 trio), `GROUP` (adds the non-vertebrate grade and the RyR outgroup in accent violet), `STATUS`/`QUALITY` (the ordered blue→grey→red evidence scales), `CLINICAL` (reserved status colours). `panel()`, `despine()`, `hgrid()`, and `save()`, which writes png+pdf at 400 dpi and **raises** rather than writing a figure whose tight bbox runs off-canvas or whose text needs a glyph the font lacks. |
| `s14_lib.py` | Manuscript-assembly shared helpers: page geometry, the section order, the main / Extended Data / Supplementary figure maps (the *plan* — source paths are where the tasks write their figures), the deposit rules, and stdlib TSV/JSON/SHA-256/PNG-size helpers. |
| `s14_figures.py` | Copies every committed figure into `manuscript/figures/` under its publication number, in every format the analysis produced. Nothing is re-plotted, so a manuscript figure cannot differ from the one in its results directory; files not in the manifest are deleted on every build. |
| `s14_claims.py` | **The manuscript's drift guard.** Every load-bearing number is declared with its source table and the op that recovers it (`count` / `cell` / `nunique` / `sum` / `json` / `grep`, with `col__startswith` and `col__in` filters). Ships with an empty `CLAIMS` list and a worked example of each op. |
| `s14_deposit.py` | Walks the deposited tree → `deposit_manifest.tsv` with size + SHA-256 per file, and `deposit_notes.md` listing the bulk classes deliberately excluded **with the command that regenerates each**. |
| `s14_pdf.py` | The typeset PDF: builds a pandoc markdown with each figure placed above its own legend, then xelatex via pandoc. Three traps are handled in code and commented there. |
| `s14_assemble.py` | The driver — ordered stages `figures → claims → stitch → deposit`; `--only` / `--from` / `--list`; non-zero exit on a missing figure, a missing section or a failed claim. |
| `s0_db_snapshot.py` | **S0 step 4** — re-derives every `[db]` number in `docs/ip3r_background.md` (InterPro signature + taxonomy counts, the UniProt reference and sister-family panel, per-protein Pfam architecture, the zebrafish PF08709 query) into `results/s0_baseline/*.tsv`. Re-run it whenever a `[db]` number is about to be quoted. |
| `s0_gene_structure.py` | **S0 step 4** — exon counts, genomic spans and cytobands for ITPR1/2/3 from Ensembl `lookup/symbol?expand=1` (deliberately *not* `xrefs/symbol`, which stalls for `homo_sapiens` — see the S0 report). This is what falsified the "~58–60 exons, hundreds of kb" claim. |
| `s0_report.py` | **S0** — renders `results/s0_baseline/report.md` purely from the committed tables (D13). Nothing in that report is hand-written. The claim-audit reference count comes from `lit_claims.tsv`, not from the size of `references.tsv`, because that table also backs the review. |
| `s0_review_build.py` | **Assembles `docs/ip3r_review_2026.md` from `docs/review/*.md`** and renders the bibliography from `references.tsv`; `--pdf` typesets it via pandoc + xelatex, `--check` validates without writing. A cited key with no reference row is a build error, so the text and the bibliography cannot drift. It also numbers the figures in order of first appearance and resolves `{fig:<slug>}` — a reference to a figure that is not placed exits 3, a placed figure whose png/pdf is missing exits 4. Rewrites `<sub>`/`<sup>` into pandoc syntax, swaps each figure's png for its vector pdf inside a `center` block (so figures stay where the text puts them), and drops the duplicate H1. |
| `s0_figdata_domains.py` | **Review-figure data** — per-protein Pfam *coordinates* from InterPro for the reference panel, the sister panel and the non-vertebrate grade → `review_figures/domain_coords.tsv`. `pfam_architecture.tsv` says which signatures a protein carries; this says where they sit, which is what lets the ITPR/RyR comparison be drawn rather than asserted. |
| `s0_figdata_structure.py` | **Review-figure data** — measures the channel from PDB **6DQN** (human IP₃R3, IP₃-bound, 3.33 Å, the review's [R24]): four-fold axis, C4 residual, pore-radius profile, the residues lining the filter and the gate, the IP₃ contacts, and the ligand→gate geometry. The 14 MB mmCIF goes to a `--work-dir` **outside the repo** (refuses a path inside it); what is committed is one C4-symmetric subunit's Cα trace, the pore profile and a measurements JSON. Self-checking: it exits non-zero unless the narrowest luminal point lands on the GGGVGD filter motif, which nothing in the geometry knows about. |
| `s0_figdata_align.py` | **Review-figure data** — two MAFFT alignments of the committed control panels: the 25-sequence family alignment (→ per-column conservation on human ITPR1 numbering) and an 8-sequence ITPR+RyR superfamily alignment (→ all-pairs identity under both metrics, and the zoom windows). The windows are anchored on the sites *measured* by `s0_figdata_structure.py`, not on a residue list from a paper. Records MAFFT's version and return code, because S1 established that a silent MAFFT failure falls back to a star alignment. |
| `s0_figdata_curated.py` | **Review-figure data** — the three hand-curated tables (milestones, regulators, disease sites) that no database returns. Every row carries the review's stable citation keys and the script **fails** if one has no reference row; no milestone year is typed in (each is read from `references.tsv`); and variant positions are recorded as `point` / `domain` / `gene` by how far the cited source actually localises them. |
| `s0_fig_lib.py` | Shared figure helpers: table loading, the domain palette (which encodes *shared with RyR* / *generic pore* / *RyR-only* rather than domain identity for its own sake), the domain-track primitive, `W_REVIEW` (the review's own text width — `figstyle.W_FULL` is the manuscript's), and `provenance()`, the corner tag that marks every figure **measured**, **computed**, **schematic** or **curated**. |
| `s0_figs_structure.py`, `s0_figs_sequence.py`, `s0_figs_genomics.py`, `s0_figs_concepts.py`, `s0_figs_clinical.py` | The 12 review figures, three or four to a module. Each renders **only** from committed tables (D13 applied to figures). |
| `s0_review_figures.py` | The figure driver — `--list`, `--only <slug>` (repeatable), else all 12; maps each slug to the section it illustrates. |
| `s1_toolchain.py` | **S1 step 1** — probes every external binary (PATH first, then the recorded conda env) and every Python package the pipeline imports, and writes `results/toolchain_manifest.txt` + `benchmark_controls/toolchain.tsv`. A tool that only exists inside the env is recorded *as* env-resident rather than silently passing as a PATH tool. |
| `s1_panels.py` | **S1 ground truth** — the two control panels and their live UniProt fetch (Swiss-Prot preferred, longest as tie-break), cached to `panel_positives.json` / `panel_decoys.json` + FASTA so the benchmark reruns offline. Positives: ITPR1/2/3 across a vertebrate panel plus the invertebrate / non-metazoan single-Itpr grade. Decoys: RYR1/2/3 across species (the sharp decoy — they carry every diagnostic Pfam), the MIR-domain sharers POMT1/2, in-band channels and non-channels, and out-of-band giants. |
| `s1_lib.py` | S1 helpers: `MafftTracer` (wraps `subprocess.run` to prove MAFFT really ran, with its return code), candidate lookup by label or dedup key, the component decoder that reads which scorer components fired back out of the evidence text, and `bait_margins()` — the ITPR-vs-RyR labelled-bait margin that operationalises D14/D7. |
| `s1_benchmark.py` | **The S1 driver** — mirrors the production wiring (live InterPro domain lookup, `analyse(use_mafft=True)`, MSA-signature fallback, `discover_novel_paralogs`) across a baseline run plus one hold-out per paralog, and writes tables only. Also measures every margin under both identity metrics (full-alignment and `covered_only=True`) and diagnoses each recall failure. |
| `s1_report.py` | **S1** — renders `results/benchmark_controls/report.md` purely from the committed tables (D13). |
| `s2_lib.py` | S2 shared helpers: the seed / context / RyR signature lists (and *why* MIR is not a seed), the two-host InterPro fetch with backoff, `signature_names()` (Pfam IDs resolved live and cached so no report hard-codes what a signature means), TSV I/O and the dashboard live-panel writer. |
| `s2_interpro.py` | **S2 step 1** — walks each seed signature to exhaustion, archiving every raw page under the data root and then re-parsing the census *out of the archive*, so the parse is reproducible offline (`--parse-only`). Resumable: the cursor is persisted after every page, and a cursor the API later rejects restarts that signature rather than silently resuming onto a shifted result set. Records InterPro's advertised `count` and UniProt's independent count beside the number actually served — which is how S2 found the advertised count is 168 short for PF08709. |
| `s2_uniprot.py` | **S2 step 2** — one streamed UniProt query returns the whole seeded space *with its full Pfam architecture* (`xref_pfam`), lineage and length, turning ~15,000 per-protein InterPro lookups into a single request. Parses UniProt's ranked lineage into rank columns plus a coarse `group` bucket. |
| `s2_call.py` | **S2 step 3** — the positive ITPR-or-RYR call on every record, on architecture (D14): RYR on any RyR-specific signature, ITPR on the *complete* IP3-receptor architecture with none of them, length as support only. Writes `census_v2.tsv`, the call summary, the conflicts, the unassigned profile, and `rule_audit.tsv` — which scores the architecture rule against gene symbols the rule never sees. |
| `s2_sequences.py` | **S2 step 4** — the seeded-space FASTA and the full representative set (both bulk, both under the data root), plus the committed per-phylum **core panel**. `load_fasta()` handles UniProt's `sp|ACC|NAME` and this project's `ACC|GENE|Species|PARALOG` headers explicitly, because reading the wrong field fails silently. |
| `s2_verify.py` | **S2 step 5** — checks the annotation-derived call against sequence: D14's labelled-bait identity margin over the core panel, under both identity metrics, scored separately inside and outside D7's no-call band (read off `DiscoveryConfig`'s own default, not retyped). |
| `s2_delta.py` | **S2 step 6** — census v1 (the app's own search bundles + S1's panels) vs census v2, by lineage, with a **verdict on every v1 accession absent from v2**; the unexplained residue is resolved against UniProt's own Pfam list rather than assumed. |
| `s2_figures.py` | The four S2 figures, rendered only from the committed census tables (D13, D19). |
| `s2_report.py` | **S2** — renders `results/census_v2/report.md` purely from the committed tables (D13). |
| `s3_hmm_lib.py` | S3 shared helpers: FASTA IO (including a streaming reader for the 8.8 GB sweep DB), UniProt FASTA-header parsing, `parse_domtblout()` / `best_hits_by_target()` (which merges domain rows into per-target coverage and takes the **full-sequence** bit score, because that is what the profile margin is measured on), and `parse_jackhmmer_log()` — which recovers each round's *included target list* as well as its counts, since D10's kill criterion has to be evaluated on evidence rather than on a total. |
| `s3_seed_spec.py` | **The committed seed manifests for both profiles**, with the five selection rules written out (census-derived labels, one seed per species per paralog, complete architecture unless the note says why not, the length band as support, the two sets disjoint and equally deep). Also `JACKHMMER_SEEDS` — the three single-sequence seeds of the convergence runs. Every deliberate exception carries its reason in the row, including Q9NA13 (*Dictyostelium* iplA, 2/5 signatures, in the ITPR set precisely so the profile can find its relatives). |
| `s3_build_seed.py` | **S3 step 1** — builds `itpr.hmm` **and** `ryr.hmm` from those manifests: pull each seed out of S2's archived seeded-space FASTA, MAFFT L-INS-i, hmmbuild. Every selection rule is *enforced*, not trusted — a seed whose census call, architecture count or length has drifted since the manifest was written aborts the build (it caught one mis-transcribed architecture count on the first run). MAFFT runs **single-threaded** (D24): at `--thread -1` it is not reproducible, and the same seeds gave profiles of 4,933 and 4,908 match states on consecutive runs. Its return code and a ragged-alignment check are hard failures (S1: a silent MAFFT failure degrades to a star alignment with no other symptom), and the SHA-256 of every seed set, alignment and profile goes into `seed_build_stats.json` so a rebuild that drifts is visible in the data. |
| `s3_assign.py` | **D14 at HMM scale**: score against both profiles, assign to the winner, and only when it beats the loser by more than `REL_MARGIN` (0.10 — D7's number) of its own score and clears `MIN_SCORE` bits. The margin is **relative** because bit scores scale with alignable length, so a fixed gap would call every full-length protein and no fragment. `audit_against()` scores the assignment against a call it never sees. Nothing here reads a gene symbol, a protein name or a length. |
| `s3_kill.py` | **D10's coded kill criterion.** Three rules evaluated per jackhmmer round on that round's own inclusion list: **K1** sister-family contamination over 5 % (the family-specific rule — an ITPR-seeded run drifting across the shared architecture into the RyRs is *the* failure mode here), **K2** a round including more than 10× the previous one, **K3** the 10-round ceiling without convergence. Rounds from the first firing on are reported but excluded from the merge. |
| `s3_fetch_proteomes.py` | **S3 step 2** — UniProt reference proteomes for a taxon group → one gzip per proteome under the data root plus a concatenated sweep DB, resumable on gzip validity. Canonical sets only: isoform sets add isoforms of genes already counted, and the census counts genes. The five groups partition Eukaryota so S20 reuses the code path without sweeping anything twice. |
| `s3_calibrate.py` | **S3 — measuring the instrument before using it.** Runs both profiles over S2's whole archived seeded space and scores the profile assignment against S2's architecture call, which read different evidence entirely. Reports agreement twice, with and without the seed accessions, because the seeds are in that set by construction. |
| `s3_run_sweep.py` | **S3 steps 2–3 driver** — both profiles' `hmmsearch` over the 8.8 GB sweep DB then the margin assignment, and the `jackhmmer` runs to convergence, per-tag so separate processes can run one seed each in parallel. `--parse-only` re-derives a run's convergence tables from its **archived log** without searching again (the S2 discipline applied to HMMER): the per-round *included target lists* D10 is evaluated on exist only in the log, so being able to re-parse them offline is what makes the kill criterion re-checkable. A re-parse carries forward the recorded runtime rather than erasing it. Writes the dashboard live panel. |
| `s3_census_v3.py` | **S3 step 4** — merges the two instruments into `results/census_v3/`: every v2 record gains its profile verdict, novel sweep hits are appended, and the merged call is a stated rule over both (D23: agree → high; one speaks → that one; disagree → `conflict`, kept and reported; neither → `unassigned`). Applies D22's gate at the merge so module-only hits are counted but not enrolled, keeping the ones carrying a family gene symbol as annotation leads. Measures completeness the expensive way round — each v2 ITPR record the sweep failed to find is **looked up in the 8.8 GB database itself**, one streaming pass, so "not in the reference proteome" is told apart from "in it and missed". Also profiles what each jackhmmer model is actually built from, by profile call × evidence class. |
| `s3_figures.py` | The four S3 figures, from the committed S3 tables only (D13, D19): profile separation with the no-call band drawn rather than described, the jackhmmer completeness curve beside its sister-contamination trace, which instrument calls each record, and per-proteome copy number against annotation depth. |
| `s3_report.py` | **S3** — renders `results/census_v3/report.md` purely from the committed tables (D13). |
| `s3_report_d10.py` | Section 4 of that report — jackhmmer, the D10 verdict per seed with its wall clock, and **what each iterated model is actually built from**. Split out of `s3_report.py` to keep both under 500 lines; it takes the caller's table loader rather than re-importing one, so the two modules cannot read the tables differently. The composition paragraph is computed per evidence class, because with three seeds the family categories agree exactly and the non-family ones do not. |
| `s4_manifest_lib.py` | S4 shared logic: `datasets` JSONL parsing, the assembly rank function (annotated > RefSeq > level > scaffold N50, D9), one-best-per-order selection, and **`derive_margins()`** — the margin species computed from the committed census tables by four stated rules (`zero_hit_proteome`, `missing_paralog` at fewer than 3 paralogs, `fragment_only` below `family.MIN_LENGTH_AA`, `anchor`) rather than hand-listed, so the denominator rebuilds from the census. Also `datasets_bin()`, since the CLI is env-resident and not on PATH. No network calls. |
| `s4_build_manifest.py` | **S4 driver** — cached `datasets` dumps → `results/genome_manifest.tsv` + `genome_manifest_notes.md`; 161 orders ∪ 169 margin species = 309 genomes. Every call is archived under `<data_root>/raw_api/ncbi_datasets/`, so a rerun is offline unless `--refresh-assemblies`. Resolves each margin species to its best assembly with the **same** rank function the order reps use — a last-wins taxid lookup put one species in twice under two accessions. |
| `s4_notes.py` | Renders `genome_manifest_notes.md` from the manifest rows (D13 applied to the scope document): the scope rule, the margin rule table with its thresholds and counts, class breakdowns, the D9 annotation-source split, the storage estimate against measured free space, and the assemblies over 10 Gbp. |
| `s5_intron_calibration.py` | **S5 step 0 — the threshold nobody can guess.** miniprot's `-G` default (200 kb) is not a performance knob: a gene whose largest intron exceeds it is *split*, and a split ITPR reads out of the ledger as `fragment`. Measures the largest single intron of ITPR1/2/3 and RYR1/2/3 across an 11-species Ensembl panel with each assembly's size, and derives the scaling rule the sweep uses. Result: **no ITPR gene in the panel has an intron over 200 kb** (widest 152 kb, human ITPR1) while the RyR control exceeds it twice (human RYR2 228 kb) — so the default is adequate for the deliverable and marginal for the control. → `results/s5_baits/intron_calibration.{tsv,json}` |
| `s5_bait_spec.py` | **The seven rules that choose the S5 bait panel**, written out and enforced rather than described: census-derived paralog labels (R1), full length *and* complete architecture (R2), one bait per paralog per clade band and two in the bands that dominate the scope (R3), the profile chimera screen (R4), the RyR baits as a presence control (R5), S3's seeds reused not re-derived (R6), and the panel scoped to this sweep's vertebrate genomes (R7). Also `band_of()`, which resolves a census row's clade band class → order — UniProt's ranked lineage has no class rank for the coelacanth, and a class-only lookup silently dropped the Latimeria seed from the first build. |
| `s5_build_baits.py` | **S5 step 1 driver** — derives the panel from `census_v3.tsv` by those rules, pulls sequences from committed/archived files only (no network), screens every candidate *and every incumbent S3 seed*, and writes the panel with its full provenance. 38 baits (30 ITPR + 8 RyR control), 121,294 residues, 25 reused seeds + 13 additions. Six slots stay unfilled — ITPR1/ITPR2 in chondrichthyans, ITPR2 in the coelacanth grade, all three in cyclostomes — because no labelled full-length record exists there; the `vertebrate_basal` baits cover those genomes unlabelled and S7 settles the paralog. → `results/s5_baits/` |
| `s5_bait_screen.py` | **D5's chimera screen, run with this project's own profiles.** Scores each candidate against `itpr.hmm` and `ryr.hmm` under S3's relative margin (family, positively — D14) and requires the winning profile's envelope to cover the bait with no large unaligned interior (shape). `self_test()` is a negative control for the screen itself, run on **every** build: three synthetic failures are constructed from real panel baits and each must be rejected by the rule responsible. | `s20_test_sensitivity.py` | **The equivalence test for S20's one-search-two-sensitivities design**, and the module that proved the design's stated assumption wrong. They do not: `--domE` is applied to the **conditional** E-value, which is normalised by how many sequences passed, so a looser `-E` inflates every c-Evalue by a constant factor (1.41× measured) and pushes marginal domains out of the report. ## `src/utils/family.py` — the family definition

**The single place the project's subject is defined.** Pfam signatures
(`FAMILY_PFAM_IDS`), the census signatures, the size band
(`MIN_LENGTH_AA`/`MAX_LENGTH_AA`, set to exclude the ~5,000 aa ryanodine
receptors), the reference panel (human ITPR1/2/3), the sister-family panel
(RYR1/2/3), the literature keyword, and the known-name substrings. Pointing
this app at another family is an edit of this file plus the presets.

## `src/databases/` — one client per source, common interface

| File | Class | Notes |
|------|-------|-------|
| `base.py` | `DatabaseClient` | Abstract; subclasses implement `search()`. |
| `ncbi.py` | `NCBIClient` | Biopython `Bio.Entrez` against the `protein` index. |
| `ensembl.py` | `EnsemblClient` | `rest.ensembl.org` `/lookup/symbol/{species}/{symbol}` → `/lookup/id?expand=1` → transcripts → translations. **S0 changed the symbol-resolution path**: `/xrefs/symbol/homo_sapiens/…` stalls indefinitely (per-species server fault, `BRCA2` too), while `lookup/symbol` works and `xrefs` still works for other species — so `xrefs` is now only a fallback. Evidence: `results/s0_baseline/ensembl_endpoint_probe.tsv`. |
| `uniprot.py` | `UniProtClient` | `rest.uniprot.org/uniprotkb/search`; surfaces canonical + named isoforms. |
| `alphafold.py` | `AlphaFoldClient` | `alphafold.ebi.ac.uk/api/prediction/{acc}` — pivots off UniProt; reports pLDDT and model URLs. |
| `foldseek.py` | `FoldseekClient` | `search.foldseek.com/api/` — async structure-based remote-homology search; opt-in. |
| `compara.py` | `ComparaClient` | **Phylogenomic paralog mining** via Ensembl Compara gene trees — every within-species paralog of the query genes, regardless of naming. Flags adjacent family loci as possible split gene models. Note: ITPRs and RYRs share a gene tree, so its paralog lists include RyRs by design. |
| `blast.py` | `BlastClient` | **Sequence-bait BLAST** via NCBI's public queue — blastp of the longest fetched sequence per gene against nr; finds homologs however they are named. Async, 2–10 min. |
| `interpro.py` | (functions) | InterPro/Pfam helpers — `list_proteins_with_pfam()` (census mode: `max_results=None` paginates to exhaustion, with `strict` failure, raw-page `dump_dir`, `stats` out-dict, and — added in S2 — `start_url`/`start_page`/`on_page` for a resumable walk, `CursorExpired` for a rejected cursor, exponential backoff to a 60 s cap, and **two-host failover** across `/interpro/api/` and `/interpro/wwwapi/`, which fail independently: during S2 the documented host answered 1 request in 12 while the website's host answered 12 of 12), `batch_fetch_family_signatures()`, `has_family_signature()`, `fetch_uniprot_sequence()`. Not in `AVAILABLE_CLIENTS`; used by discovery + domain scan. |

`AVAILABLE_CLIENTS: dict[str, type[DatabaseClient]]` in
`databases/__init__.py` is what the orchestrator looks up by name;
`SEQUENCE_SOURCES` / `STRUCTURE_SOURCES` group them for the UI, and
`BAIT_SOURCES` (`BLAST`, `Foldseek`) marks clients the orchestrator runs
*after* the sequence DBs, feeding them the longest fetched sequence per gene
as bait.

## `src/discovery/` — novel-paralog hunter

| File | Key types / functions |
|------|-----------------------|
| `candidates.py` | `DiscoveryConfig`, `Candidate`, `DiscoveryReport`, `discover_novel_paralogs(…)`. Composite 8-criterion scorer + **promotion evidence gate** (D3: score ≥ 40 requires ≥ 1 family-specific component — outlier / domain / fold / split — else capped at 39) + the **sister-family test** (D14/D7, added in S1): a candidate closer to a labelled RyR bait than to any known ITPR paralog, by more than `sister_margin` (0.10), is assigned to the sister family and capped at 39, with the margin recorded. It is a positive test on distances — the candidate's own gene symbol is never consulted — and the length band is deliberately not part of the call. Without it all six RyR decoys were promoted at 45. Defaults read from `utils/family.py`. |
| `domain_scan.py` | `run_domain_scan(…)` — the fourth-paralog hunt: enumerate every protein with a family Pfam ID via InterPro, filter out known paralogs *and the ryanodine receptors*, fetch sequences, run analysis + discovery. |
| `exhaustive.py` | `run_exhaustive_hunt(…)` — the all-in-one `"mode": "exhaustive"` pipeline: Compara mine + ortholog expansion + InterPro enumeration → merged census (`itpr_like_census.csv` + FASTA) → analyse + discovery + presence matrix + highlighted tree + bundle/report. |

## `src/cli.py` — headless pipeline

`run_headless(project_root, preset, …, analyze, discover, interpro_lookup,
save_results)`: load preset → build `SearchQuery` (`"mode": "domain_scan"`
presets route to `run_domain_scan`) → `SearchOrchestrator` fans queries →
optional `analyse()` → optional `discover_novel_paralogs()` → optional
`write_bundle()` + `write_report()`.
`run_investigate(project_root, accession, …)` deep-dives one accession.

## Data Flow

```
SearchPanel.on_search ──▶ MainWindow._on_search ──▶ SearchOrchestrator.start
                                                          │
                                            ┌─────────────┼─────────────┐
                                            ▼             ▼             ▼
                                   NCBI / Ensembl / UniProt / Compara / AlphaFold
                                            │             │             │
                                            └────────┬────┴─────────────┘
                                                     ▼
                                          (sequence DBs done)
                                                     ▼
                                gather longest sequences ──▶ BLAST + Foldseek
                                                     ▼
                                                queue.Queue
                                                     ▼
                                  MainWindow._drain_queue (after())
                                                     ▼
                                              ResultsView.extend
                                                     ▼
                                                DetailsView.show
```

Post-search, the **Analysis menu** (`ToolsController` + `TaskRunner`) runs
`analyse()` / `discover_novel_paralogs()` / `run_domain_scan()` /
`Investigator` on a worker thread and shows results in `TextWindow`s.
